# Extends — Game Design Document

Oct 18, 2026 · @fiafia

## ภาพรวมเกม

**Extends** (ชื่อชั่วคราว) คือเกมฟรีสอนเขียน TypeScript ที่ผู้เล่นเป็นนักวิทย์ฝึกหัด สร้างสัตว์ประหลาดด้วย `class` แล้วปล่อยให้มันทำงานอัตโนมัติในแล็บ โค้ดที่เขียนกำหนดทั้ง **หน้าตา** และ **พฤติกรรม** ของสัตว์

**Elevator pitch:** "เขียน `class FireSlime extends Slime` แล้วดูสไลม์ของคุณลุกเป็นไฟต่อหน้า"

### เสาหลักของการออกแบบ

ทุกฟีเจอร์ต้องตอบได้ว่าช่วยเสาไหน ถ้าไม่ช่วยเลยให้ตัดทิ้ง

1. **โค้ดคือสิ่งมีชีวิต** ทุกบรรทัดที่เขียนต้องเห็นผลบนจอ ไม่มีโค้ดที่ "มองไม่เห็น"
2. **เจ็บก่อน แล้วค่อยปลดล็อก** concept ใหม่มาตอนที่เครื่องมือเดิมเริ่มทำให้ลำบาก ผู้เล่นจึงเข้าใจว่ามันมีไว้แก้ปัญหาอะไร
3. **ผู้เล่นออกแบบ ระบบรันเอง** ความสะใจอยู่ที่การนั่งดูแล็บที่ตัวเองเขียนทำงานไปเรื่อยๆ
4. **สะสมแล้วอยากได้อีก** สมุดสะสมสายพันธุ์และสูตรลับทำให้มีเหตุผลเล่นต่อหลังจบบทเรียน

### กลุ่มเป้าหมายและแพลตฟอร์ม

- **กลุ่มหลัก:** มือใหม่ที่เพิ่งเริ่มเรียน JS/TS อายุ 15 ปีขึ้นไป รวมถึงนักเรียน bootcamp
- **กลุ่มรอง:** dev ที่เขียนเป็นแล้วแต่อยากเข้าใจ OOP ให้ลึก และสายชอบเกม optimize
- **แพลตฟอร์ม:** เว็บ (เปิดลิงก์เล่นได้ทันที ไม่ต้องติดตั้ง) และ Steam (ให้คนทั่วไปค้นเจอ) แจกฟรีทั้งคู่ เล่นบนคอมพิวเตอร์ที่มีคีย์บอร์ดเท่านั้น ไม่ทำเวอร์ชันมือถือ
- **ภาษา:** ไทยและอังกฤษตั้งแต่วันแรก

## โลกและเรื่องราว

ผู้เล่นได้รับมรดกเป็นแล็บร้างของ **ศาสตราจารย์ Null** ที่หายตัวไปอย่างลึกลับ เหลือไว้แค่สไลม์ตัวเดียว หุ่นผู้ช่วย และสมุดบันทึกที่ขาดหายเป็นท่อนๆ

เรื่องเล่ามีหน้าที่เดียว คือ **ให้เหตุผลกับทุกบทเรียน** ทุกครั้งที่ผู้เล่นต้องเรียน concept ใหม่ ต้องมีปัญหาในเรื่องที่บีบให้ต้องใช้มัน

### ตัวละคร

| ตัวละคร | บทบาท | หน้าที่ในการสอน |
| --- | --- | --- |
| ผู้เล่น | นักวิทย์ฝึกหัด เจ้าของแล็บคนใหม่ | ผู้เขียนโค้ดทั้งหมด |
| **Ref** | หุ่นผู้ช่วยขี้บ่น พูดเหมือน linter | ให้ hint, อธิบาย error เป็นภาษาคน, เป็นเสียงของ tutorial |
| **ศ. Null** | ผู้สร้างแล็บที่หายไป | หน้าบันทึกที่เก็บได้ = เอกสารอธิบาย concept แต่ละเรื่อง |
| **Monolith Corp** | บริษัทคู่แข่งที่ผลิตสัตว์แบบ copy-paste ไม่ใช้ class | ตัวแทน "โค้ดแย่" ผู้เล่นเห็นผลเสียของมันจริงๆ |

### โครงเรื่อง 5 องก์

1. **ตื่นในแล็บร้าง** ไฟดับ เครื่องจักรพัง มีแค่สไลม์ตัวเดียว ผู้เล่นต้องสั่งมันเก็บพลังงานมาซ่อมแล็บ
2. **โรงฟักไข่** ซ่อมโรงฟักได้ แต่งานเยอะเกินกว่าสไลม์ตัวเดียวจะทำไหว ต้องผลิตสัตว์เป็นฝูง
3. **กำเนิดสายพันธุ์** ห้องใหม่ๆ (เตาหลอม บ่อน้ำ หอคอย) ต้องการสัตว์ที่มีความสามารถเฉพาะ จึงเกิดตระกูลสัตว์
4. **วิกฤต Monolith** สัตว์ของ Monolith Corp บุกเข้ามาแก้ค่าพลังสัตว์ของเรามั่ว และผู้เล่นต้องการสัตว์ผสมหลายธาตุจน inheritance รับไม่ไหว
5. **ลงสู่ Prototype** สมุดบันทึกชี้ว่าศาสตราจารย์ลงไปใน "Prototype" ชั้นลึกสุดที่สิ่งมีชีวิตทุกตัวสืบทอดมา บอสสุดท้ายคือ **The Monolith** สัตว์ยักษ์ที่เป็น class เดียวยาวห้าพันบรรทัด ผู้เล่นชนะด้วยการ **refactor** แยกมันออกเป็นชิ้นส่วน

ตอนจบเฉลยว่า class ทั้งหมดที่ผู้เล่นเขียนมาจริงๆ แล้วต่อกันเป็น prototype chain และศาสตราจารย์ Null กลายเป็นรากของทุกสายพันธุ์ ซึ่งเป็นการสอนว่า class ใน JS คือ syntax ที่ครอบ prototype ไว้

## Core loop

ผู้เล่นเขียน class หนึ่งครั้ง แล็บทำงานเองไปเรื่อยๆ จนได้ของใหม่มาปรับโค้ดอีกรอบ

```
เขียน/แก้ class ──กด save──▶ สัตว์เกิดและเปลี่ยนร่าง (new + Morph)
      ▲                                   │ ทุก tick
      │ ของใหม่ให้ใช้                        ▼
ได้ทรัพยากรไปวิจัย ◀──เก็บของ── สัตว์ทำงานเอง (engine เรียก update())
   (วงแก้บั๊ก: สัตว์ทำงานเอง ──บั๊ก?──▶ กลับไปแก้ class)
```

วงหลักหมุนตามเข็มนาฬิกา ส่วนเส้นประคือวงแก้บั๊กสั้นๆ ที่ผู้เล่นวนบ่อยที่สุด

### สามจังหวะเวลา

- **ระดับนาที:** แก้โค้ด → save → ดูสัตว์ → เจอบั๊ก → แก้ ต้องเร็วและไม่ลงโทษ
- **ระดับชั่วโมง:** สะสมทรัพยากรจนพอวิจัย → ปลดล็อกชิ้นส่วนหรือ concept → สร้างสายพันธุ์ใหม่เข้าห้องใหม่
- **ระดับทั้งเกม:** จบภารกิจเนื้อเรื่อง → ได้หน้าบันทึก → เปิดองก์ใหม่และเติมสมุดสะสม

เวลาในแล็บเดินต่อระหว่างที่ผู้เล่นพิมพ์ (ยกเว้นกดหยุด) ทำให้ได้ความรู้สึกแบบเกม idle คือโค้ดดีๆ ที่เขียนไว้ยังทำงานให้อยู่ตลอด

## ระบบหลัก

เกมมี 6 ระบบที่ส่งต่อกันเป็นวง: เขียน class สร้างสัตว์ สัตว์ทำงานหาทรัพยากร ทรัพยากรเอาไปวิจัย การวิจัยปลดล็อกชิ้นส่วนและ concept ใหม่

### 1. สร้างสัตว์ด้วย class

เกมมี base class `Creature` ให้ ซึ่งมีค่าพื้นฐาน (hp, energy, hunger) และ method พื้นฐาน (`move`, `eat`, `gather`, `rest`, `say`) ผู้เล่นเขียน class ของตัวเองแล้ว engine จะเรียก `update()` ของสัตว์ทุกตัวทุก tick เอง

```ts
class Slime extends Creature {
  body = "blob"
  update() {
    if (this.hunger > 50) this.eat()
    else this.gather(nearest("essence"))
  }
}
```

การ `new` สัตว์แต่ละตัวใช้ Essence ทำให้ผู้เล่นต้องคิดว่าจะสร้างอะไรก่อน

### 2. ประกอบร่างจากโค้ด (Morph)

หัวใจของเกม: property ใน class แปลงเป็นชิ้นส่วนบนตัวสัตว์ทันทีที่กด save โดยสัตว์ที่มีอยู่แล้วในแล็บเปลี่ยนร่างสดๆ โดยไม่เสียค่าที่สะสมไว้

| โค้ด | สิ่งที่เห็นบนจอ |
| --- | --- |
| `body = "blob" / "quad" / "serpent" / "bird"` | รูปร่างหลัก |
| `element = "fire" / "water" / "earth" / "air" / "void"` | สี ลาย และเอฟเฟกต์อนุภาค |
| `eyes`, `horns`, `wings`, `tail` | ชิ้นส่วนที่งอกเพิ่ม |
| `constructor(size)` | ขนาดตัวต่างกันในแต่ละ instance |
| `speak()` ที่ override | ข้อความในลูกโป่งคำพูด |
| `extends` | ชิ้นส่วนที่ได้จาก class แม่เป็นเส้นปกติ ชิ้นที่เพิ่มใหม่มีแสงเรือง |

ฝั่งทีมทำ art วาดแค่ชิ้นส่วนไม่กี่สิบชิ้น แต่ประกอบได้เป็นพันแบบ

### 3. ทรัพยากร

| ทรัพยากร | ได้จาก | ใช้ทำอะไร |
| --- | --- | --- |
| **Essence** | สัตว์เก็บในทุ่งและห้องต่างๆ | `new` สัตว์ตัวใหม่ |
| **Crystal** | ห้องเฉพาะทาง (เหมือง เตาหลอม) | วิจัย tech tree |
| **Mana** | เพิ่มตามจำนวนห้องที่ซ่อม | งบคำสั่งต่อ tick ของทั้งแล็บ โค้ดที่ประหยัดกว่าทำให้เลี้ยงสัตว์ได้มากกว่า |
| **หน้าบันทึก** | ทำภารกิจเนื้อเรื่องสำเร็จ | ปลดล็อก concept ภาษาใหม่ |

Mana ทำให้เรื่องประสิทธิภาพของโค้ดมีผลจริงในเกม โดยไม่ต้องบรรยายทฤษฎี

### 4. ห้องในแล็บ

แต่ละห้องรับเฉพาะสัตว์ที่มีคุณสมบัติตรง ทำให้ผู้เล่นต้องสร้างสายพันธุ์ใหม่ และในองก์ 4 กลายเป็น interface ของ TypeScript

- **ทุ่ง Essence** รับทุกตัว
- **เตาหลอม** เฉพาะธาตุไฟ
- **บ่อน้ำ** เฉพาะ `Swimmer`
- **หอคอย** เฉพาะ `Flyer`
- **เหมืองคริสตัล** เฉพาะ `Digger`
- **ห้องฟักไข่** ใช้สอน async (ไข่ใช้เวลาฟัก)

### 5. การวิจัย (Tech tree)

แบ่งเป็นสองสาย ใช้ Crystal ปลดล็อก

- **สายภาษา:** concept ใหม่ เช่น for loop, class, extends, private field ถ้าเขียน syntax ที่ยังไม่ปลดล็อก editor จะขึ้นแม่กุญแจที่บรรทัดนั้น
- **สายชิ้นส่วน:** รูปร่าง ธาตุ และอวัยวะใหม่สำหรับประกอบร่าง

### 6. สมุดสะสม (Codex)

- มีสายพันธุ์ประมาณ 60 ถึง 100 แบบ ค้นพบเมื่อผู้เล่นเขียน class ที่ตรงกับ "สูตร" เช่น สายสืบทอดหรือชุดธาตุที่กำหนด
- บางสายพันธุ์เป็นความลับ ต้องเดาสูตรจากคำใบ้ในบันทึกของศาสตราจารย์
- มีหน้า **ผังตระกูล** วาด class hierarchy ทั้งหมดที่ผู้เล่นเขียนเป็นต้นไม้ เท่ากับ UML ที่สร้างเองโดยไม่รู้ตัว

## Curriculum

ทั้งเกมสอน 16 concept เรียงจาก object ไปถึง prototype chain โดยทุก concept มี "ความเจ็บ" ที่ผู้เล่นต้องเจอก่อนปลดล็อก ช่องนั้นสำคัญที่สุดในตาราง เพราะเป็นตัวบอกว่าผู้เล่นจะเข้าใจว่า concept นี้มีไว้ทำไม

| องก์ | Concept | ความเจ็บที่ปูทาง | ภารกิจตัวอย่าง |
| --- | --- | --- | --- |
| 1 | object, property, เรียก method | (บทเปิด) | สั่งสไลม์เก็บ Essence 5 ก้อน |
| 1 | ตัวแปร, if/else | สั่งแค่เก็บของ สไลม์เลยหิวจนหมดแรง | ให้กินเมื่อ hunger เกิน 50 |
| 1 | loop, array | ต้องเขียนคำสั่งเก็บซ้ำ 10 บรรทัด | เก็บ Essence ให้หมดทุ่ง |
| 2 | function | copy โค้ดชุดเดิมไปหลายที่ | เขียน `gatherAll()` ใช้ซ้ำ |
| 2 | class, constructor, `new` | ต้องเขียน object สไลม์ทีละตัว 10 ตัว | สร้างฝูงสไลม์ 10 ตัว ชื่อไม่ซ้ำ |
| 2 | `this` | ทุกตัวกินพร้อมกันเพราะใช้ตัวแปรร่วม | ให้แต่ละตัวกินตามความหิวของตัวเอง |
| 3 | `extends`, `super` | ต้องเขียน Slime ใหม่ทั้ง class เพื่อทำเวอร์ชันไฟ | สร้าง FireSlime เข้าเตาหลอม |
| 3 | override, polymorphism | if/else เช็คชนิดสัตว์ยาวเป็นหน้า | พิธีปลุกแล็บ `creatures.forEach(c => c.speak())` |
| 3 | map, filter, reduce | loop ซ้อนกันหลายชั้นเพื่อคัดสัตว์ | ส่งเฉพาะสัตว์ไฟไปเตาหลอม |
| 4 | private field, getter/setter | สัตว์ Monolith แอบแก้ค่า hp ของเรา | ป้องกันค่าพลังจากโค้ดภายนอก |
| 4 | interface, type | สัตว์จมน้ำตอน runtime เพราะว่ายไม่เป็น | บ่อน้ำรับเฉพาะ `Swimmer` |
| 4 | composition (ระบบยีน) | class ระเบิดเป็นสิบเพื่อผสม ไฟ+น้ำ+ปีก | `new Creature({ genes: [Fire, Water, Wings] })` |
| 5 | event, callback | เช็คสภาพอากาศทุก tick จน Mana หมด | สัตว์หลบเข้าที่กำบังเมื่อพายุมา |
| 5 | async/await, `Promise.all` | ส่งสำรวจทีละตัว ช้ามาก | ฟักไข่ และส่งทีมสำรวจพร้อมกัน |
| 5 | generics | ต้องสร้างกรงแยกให้ทุกชนิด | `Cage<T>` ที่ใส่สัตว์ได้ทุกชนิดอย่างปลอดภัย |
| 5 | prototype chain | (บทจบ) | ไขปริศนาศาสตราจารย์ Null และ refactor บอส |

**ภาษาในเกม:** องก์ 1 ถึง 3 เขียนแบบ JS ล้วน (type ไม่บังคับ) แล้ว TypeScript ค่อยๆ เข้ามาในองก์ 4 ตอนที่ interface ช่วยกันบั๊กได้จริง ผู้เล่นจะเห็นเองว่า type มีประโยชน์

## ผู้เล่นใหม่และความยาก

เกมต้องทำให้คนไม่เคยเขียนโค้ดเห็นผลจากบรรทัดแรกภายใน 30 วินาที และต้องไม่ทำให้คนเขียนเป็นแล้วเบื่อก่อนถึงส่วนสนุก

### 5 นาทีแรก

1. **0:00 ฉากเปิด** แล็บของศาสตราจารย์ตอนรุ่งเรือง สัตว์หลายสิบตัววิ่งทำงาน ผู้เล่นเห็นปลายทางของเกมก่อนเริ่ม
2. **0:30 แล็บพัง** ไฟดับ สัตว์หายหมด เหลือสไลม์ตัวเดียวทำหน้างง
3. **1:00 บรรทัดแรก** editor มีโค้ดเขียนไว้แล้วครึ่งบรรทัด `slime.` ผู้เล่นพิมพ์ต่อแค่ `jump()` สไลม์กระโดดทันที ไม่มีหน้าจออธิบายก่อน
4. **2:00 ตั้งชื่อ** ผู้เล่นพิมพ์ `slime.name = "..."` ชื่อขึ้นเหนือหัว สร้างความผูกพันตั้งแต่ต้น
5. **3:00 ภารกิจแรก** สั่งเก็บ Essence ให้ไฟห้องแรกติด แล็บสว่างขึ้นหนึ่งห้อง
6. **5:00 ตะขอ** Ref เปิดบันทึกหน้าแรกของศาสตราจารย์ ที่วาดรูปสไลม์มีปีกไว้ ผู้เล่นรู้ว่าเกมจะพาไปไหน

กฎ: ห้ามมีข้อความอธิบายยาวกว่า 2 บรรทัดใน 5 นาทีแรก ทุกอย่างสอนผ่านการลงมือ

### ปุ่มข้ามบทเรียน

- ทุกองก์มี **"ทดสอบข้าม"** เป็นโจทย์สั้นที่ใช้ concept ทั้งองก์ ผ่านแล้วได้ทรัพยากรและการวิจัยขององก์นั้นทันที
- เลือกได้ตอนเริ่มเกมว่า **"ไม่เคยเขียนโค้ด"** หรือ **"เขียนเป็นแล้ว"** แบบหลังเริ่มที่โจทย์ทดสอบข้ามองก์ 1 เลย
- เนื้อเรื่องที่ข้ามไปอ่านย้อนหลังได้ในสมุดบันทึก

### ผู้เล่นก็อปคำตอบจาก AI

เลี่ยงไม่ได้ จึงออกแบบให้ไม่สำคัญแทนการห้าม

- **รางวัลอยู่ที่การผสม ไม่ใช่การผ่านด่าน:** สัตว์ที่ได้ขึ้นกับสิ่งที่ผู้เล่นเลือกเขียนเอง ก็อปมาก็ได้แค่สัตว์ของคนอื่น
- **โจทย์ขึ้นกับสถานะแล็บ:** ตำแหน่งทรัพยากรและสัตว์สุ่มจาก seed ของแต่ละเซฟ คำตอบสำเร็จรูปจึงใช้ตรงๆ ไม่ค่อยได้
- **Challenge mode วัดการ optimize:** มีหลายคำตอบที่ถูก การได้คะแนนดีต้องลองและปรับเอง
- **ไม่ลงโทษ:** คนที่ใช้ AI ช่วยแล้วอ่านเข้าใจก็ยังได้เรียน เกมไม่ต้องทำตัวเป็นตำรวจ

## สิ่งที่ทำให้สนุก

ความสนุกของเกมสอนโค้ดต้องมาจากเกมเพลย์ ไม่ใช่การให้รางวัลหลังเรียนเสร็จ เกมนี้ออกแบบให้มี 5 ช่วง "ว้าว" ที่ตั้งใจวางไว้ บวกกับระบบที่ทำให้เล่นต่อได้ยาว

### 5 ช่วงว้าวที่ออกแบบไว้

1. **`new` ครั้งแรก** สไลม์ตัวใหม่ดีดตัวออกมาจากโรงฟัก พร้อมชื่อที่ผู้เล่นตั้งเอง
2. **แก้ class แม่ ลูกทั้งตระกูลเปลี่ยน** เพิ่ม `horns = 2` ใน Slime แล้วสไลม์ทุกสายพันธุ์ในแล็บงอกเขาพร้อมกัน
3. **คณะประสานเสียง** `forEach(c => c.speak())` แล้วสัตว์ทุกตัวร้องเสียงของตัวเองพร้อมกัน
4. **กำแพง inheritance** ผู้เล่นติดกับ class สิบกว่าตัว แล้วระบบยีนแก้ทุกอย่างในบรรทัดเดียว
5. **บอส refactor** The Monolith ถูกแยกเป็นชิ้น แล้วชิ้นส่วนกลายเป็นยีนใหม่ให้ผู้เล่นใช้

### ความลับและ easter egg

- สูตรสายพันธุ์ลับ เช่น method ที่เรียกตัวเอง (recursion) ได้งู **Ouroboros** ที่กินหางตัวเอง
- ตั้งชื่อ class ว่า `Cat` แบบไม่ extends อะไรเลย ได้แมวจรที่ไม่ยอมทำงาน
- `console.log("Hello, World")` ครั้งแรก ได้ achievement พิเศษ
- หน้าบันทึกลับของศาสตราจารย์ที่ซ่อนอยู่ใน error message บางแบบ

### Challenge mode (สำหรับสายเก่ง)

โจทย์แยกที่ให้คะแนนสามแกน: จำนวน tick, จำนวนบรรทัด และ Mana ที่ใช้ เมื่อทำเสร็จจะเห็นกราฟว่าคะแนนเราอยู่ตรงไหนเทียบกับผู้เล่นทั้งหมด ผ่าน Steam leaderboard ทำให้คนที่เรียนจบแล้วยังกลับมาเล่นต่อเพื่อ optimize

### Achievement ตัวอย่าง

- **Speciation:** สร้าง class ที่ extends ลึก 5 ชั้น
- **Zero Waste:** ผ่านด่านโดยใช้ Mana ไม่ถึงครึ่ง
- **Gotta Class 'Em All:** ค้นพบครบทุกสายพันธุ์
- **No Copy-Paste:** จบองก์ 4 โดยไม่มี class ไหนซ้ำซ้อนกัน

### หลังเล่นจบ (หลัง 1.0)

- **Steam Workshop:** แชร์ class สัตว์เป็น "การ์ดสัตว์" ที่มีทั้งโค้ดและภาพประกอบร่าง ให้คนอื่นโหลดไปใช้
- **Arena:** ส่ง AI สัตว์ของตัวเองไปสู้กับ AI ของคนอื่นแบบไม่ต้องออนไลน์พร้อมกัน

## ตัวละครและความน่ารัก

ความน่ารักคือรางวัลที่ผู้เล่นได้ทุกครั้งที่ผสม ถ้าสัตว์ที่ออกมาน่ารักหรือตลก ผู้เล่นจะลองผสมต่อเองโดยไม่ต้องมีภารกิจบังคับ ซึ่งแปลว่าได้ฝึกเขียน class เพิ่มแบบไม่รู้ตัว

### หลักออกแบบความน่ารัก

- **สัดส่วน chibi:** ตัวกลม เตี้ย หัวโตเกือบเท่าลำตัว
- **ตาคือชิ้นส่วนสำคัญที่สุด:** ทำตา 6 ถึง 8 อารมณ์ (ปกติ ดีใจ ง่วง งง ตกใจ ภูมิใจ) ให้สัตว์แสดงสถานะได้โดยไม่ต้องมีหลอดค่า
- **ไม่เคยนิ่ง:** เด้งดึ๋ง หายใจ กะพริบตา แบบ squash and stretch แม้ตอนยืนเฉยๆ
- **สีพาสเทลสดใส:** แต่ละธาตุมีโทนชัดเจน
- **ไม่มีตัวน่ากลัว:** แม้ธาตุ void ก็น่ารักแบบซนๆ ไม่ใช่สยอง

### ทำให้การผสมสนุก

- **ทุกชุดผสมต้องดูดี:** ชิ้นส่วนทุกชิ้นมีจุดยึดมาตรฐาน ไม่มีชุดไหนออกมาดูพัง
- **ผสมแปลกได้ผลตลก ไม่ใช่ error:** ปีกเล็กบนตัวใหญ่ได้ตัวที่กระพือปีกสุดแรงแต่บินได้แค่กระโดด, ไฟผสมน้ำมีไอน้ำพุ่งออกหูตลอดเวลา
- **นิสัยตามธาตุ:** ไฟใจร้อนวิ่งเร็วแต่หิวไว, น้ำขี้เกียจ, ดินขยันแต่ช้า, ลมขี้เล่นชอบหลงทาง ผู้เล่นต้องเขียน `update()` ให้เข้ากับนิสัย ซึ่งเป็นเหตุผลให้ override method
- **ชื่อผสมอัตโนมัติ:** เกมตั้งชื่อเล่นจากชิ้นส่วน เช่น Fire + Slime เป็น "Flamelime" (มีชุดชื่อไทยแยก) ผู้เล่นเปลี่ยนเองได้
- **ช่วงเกิดต้องเป็นโชว์:** ไข่สั่น แตก แล้วสัตว์ทำท่าประจำตัวพร้อมเสียงร้อง เสียงประกอบจากชิ้นส่วนและเปลี่ยนระดับเสียงตามขนาดตัว
- **รู้ตัวว่ากำลังจะเปลี่ยน:** ตอนผู้เล่นแก้ class สัตว์ตัวนั้นหันมามองจอด้วยตาเป็นประกาย

### ตัวละครหลัก

| ตัวละคร | หน้าตา | บทบาท |
| --- | --- | --- |
| **สไลม์ตัวแรก** (ผู้เล่นตั้งชื่อ) | สไลม์กลมสีฟ้าอ่อน ตาโต | มาสคอตของเกม ตามผู้เล่นทั้งเรื่องและเปลี่ยนร่างตามโค้ดที่เขียน ผูกพันเหมือนสัตว์เลี้ยงตัวแรก |
| **Ref** | หุ่นกลมตัวเล็กลอยได้ หน้าเป็นจอแสดงอารมณ์ | ผู้ช่วยขี้บ่น ทำหน้าเอือมเวลาเจอโค้ดซ้ำ |
| **สัตว์ของ Monolith** | ทรงเหลี่ยม แข็งทื่อ สีเทา กระตุกเหมือน glitch | ตัดกับสัตว์กลมๆ ของผู้เล่น เป็นภาพแทน "โค้ด copy-paste แข็งทื่อ" กับ "โค้ดที่ออกแบบดี" |

### เกมที่ควรศึกษา

- **Slime Rancher:** สไลม์น่ารักที่ผสมกันได้ ใกล้เคียงอารมณ์ที่ต้องการที่สุด
- **Spore (Creature Creator):** ระบบประกอบร่างจากชิ้นส่วนที่ทุกชุดยังมีชีวิตชีวา
- **Pokémon:** การออกแบบตัวที่จำได้จากเงา และแรงขับให้สะสม
- **Tamagotchi:** สัตว์ที่สื่อสถานะผ่านหน้าตาและท่าทาง

## Art system (pixel 32×32)

สัตว์ทุกตัวประกอบจากชิ้นส่วนบนระบบ slot และจุดยึด งานวาดจึงโตแบบบวก (ร่าง + ชิ้นส่วน) ขณะที่จำนวนแบบที่ผสมได้โตแบบคูณ เครื่องมือทดสอบคือ Morph Lab

### ทำไมจำนวนอย่างเดียวไม่พอ

ชุดแรกที่ทดสอบผสมได้ประมาณ 36,000 แบบ แต่หลายแบบมีเงา (silhouette) เหมือนกัน คนแยกตัวละครจากรูปทรงก่อนสีและรายละเอียด แกนที่เพิ่มต้องเปลี่ยนรูปทรงหรือรูปลักษณ์จริงๆ

### Slot และจุดยึด

- ร่างแต่ละแบบประกาศจุดยึดของตัวเอง: หัว (กลาง, ด้านใน, ด้านนอก), แนวตา, หลัง, ก้น, เท้า
- ชิ้นส่วนประกาศแค่ว่าอยู่ slot ไหนและวาดชั้นไหน (หลังตัว, บนตัว, หน้าสุด)
- เพิ่มร่างใหม่ 1 แบบ ชิ้นส่วนทุกชิ้นใช้ได้ทันที เพิ่มชิ้นส่วน 1 ชิ้น ใช้ได้กับทุกร่าง
- จุดยึดขยับตาม squash and stretch จึงได้ animation ของชิ้นส่วนฟรี

### แกนความหลากหลาย

| แกน | ตัวเลือก | งานวาด |
| --- | --- | --- |
| ร่าง | สไลม์, สี่ขา, นก, งู, เม็ดถั่ว, ขนปุย | วาดหรือนิยามรูปทรงทีละร่าง |
| ขนาด | เล็ก, กลาง, ใหญ่ | ไม่มี เป็นตัวเลขใน `constructor` |
| ธาตุหลัก + ธาตุรอง | 6 ธาตุ ผสมเป็นคู่ได้ 10 แบบ เช่น ไฟ+น้ำ = ไอน้ำ | ชุดสีและอนุภาค |
| โทนสี | ปกติ, อุ่น, เย็น, หายาก (shiny) | ไม่มี คำนวณจากพาเลตต์ |
| ลาย | ท้องขาว, จุด, ลายขวาง, หน้ากาก, สองโทน | mask ที่ใช้ได้ทุกร่าง |
| ตา | 7 อารมณ์ | ชิ้นละไม่กี่พิกเซล |
| ชิ้นส่วน | เขา, หู, ปีก, หาง | ชิ้นละ 1 pattern ต่อขนาด |
| ของตกแต่ง | โบว์, ดอกไม้, หมวก, มงกุฎ | ชิ้นละไม่กี่พิกเซล |

เป้าหมายเวอร์ชันเต็ม: ร่าง 8, ชิ้นส่วนหัว 12, หลัง 6, หาง 6, ลาย 8, ของตกแต่ง 10 ผสมได้หลักหลายร้อยล้านแบบ จากงานวาดประมาณ 80 ชิ้น

### กฎความน่ารัก

1. **หนึ่ง slot หนึ่งชิ้น:** กลางหัว (เปลวไฟ, ต้นอ่อน, หมวก, มงกุฎ), ด้านใน (เขา, โบว์, ดอกไม้), ด้านนอก (หู) ถ้าชนกัน ชิ้นที่สำคัญกว่าชนะ
2. **งบหัวไม่เกิน 3 แต้ม:** ชิ้นเล็ก 1 แต้ม ชิ้นใหญ่ 2 แต้ม เกินแล้วตัดของตกแต่งก่อน แล้วค่อยตัดหู
3. **สีมาจากพาเลตต์ของร่าง:** ชิ้นส่วนอ้างตำแหน่งในพาเลตต์ (ฐาน, สว่าง, เงา) ทุกชุดจึงเข้ากัน
4. **ไม่มีอะไรทับตา:** ตาวาดชั้นบนสุดเสมอ
5. **ต้องอ่านออกที่ขนาดจริง ×1:** ชิ้นไหนดูไม่ออกที่ 32px ไม่ผ่าน

### Procedural กับวาดมือ

ตัวส่วนใหญ่มาจากระบบประกอบ ส่วนสายพันธุ์ลับใน Codex (Ouroboros, แมวจร, ร่างศาสตราจารย์) วาดมือเป็น sprite เฉพาะ เพื่อให้รู้สึกเป็นรางวัลจริงๆ

### Pipeline

- วาดชิ้นส่วนใน Aseprite เป็น sprite sheet PNG พร้อมไฟล์ JSON บอก slot, จุดยึด และชั้นการวาด
- ชิ้นที่ดูแปลกกับร่างใดร่างหนึ่ง ทำเวอร์ชันเฉพาะร่างนั้นได้ ถ้าไม่มีจะใช้เวอร์ชันกลาง
- ทุกครั้งที่เพิ่มชิ้นใหม่ เปิดหน้าตารางชิ้นส่วน × ร่างใน Morph Lab เพื่อดูทุกคู่ในหน้าเดียว

ระบบนี้ตรงกับบทเรียนในเกม: ร่างคือ base class (inheritance) ส่วนธาตุรอง ลาย และของตกแต่งคือยีน (composition)

## เสียงและดนตรี

เกมน่ารักแนวนี้ เสียงทำงานเกือบเท่าภาพ: เสียงเด้งของสไลม์คือสิ่งที่ทำให้มัน "มีชีวิต" เริ่มด้วยเสียงฟรีแบบ CC0 ใน prototype แล้วค่อยจ้างทำเสียงเฉพาะตัวเมื่อเกมนิ่ง

### แนวทาง

- **เพลง:** lo-fi หรือ chiptune นุ่มๆ จังหวะช้า ฟังขณะเขียนโค้ดนานๆ ไม่เบื่อ แต่ละห้องในแล็บมีเครื่องดนตรีของตัวเองซ้อนเพิ่มเข้ามา ยิ่งซ่อมห้องได้มาก เพลงยิ่งเต็ม
- **เสียงสัตว์ประกอบจากชิ้นส่วน:** ลำตัวกำหนดเสียงฐาน (blob เป็นเสียงเด้งนุ่ม bird เป็นเสียงจิ๊บ) ธาตุเพิ่มเอฟเฟกต์ (ไฟมีเสียงฟู่ น้ำมีเสียงฟอง) ขนาดตัวกำหนดระดับเสียงสูงต่ำ ทำด้วย Web Audio API ได้โดยไม่ต้องอัดเสียงใหม่ทุกสายพันธุ์
- **เสียงตอบสนองโค้ด:** save สำเร็จเป็นเสียงกริ๊งเบาๆ, error เป็นเสียงงงของสัตว์ (ไม่ใช่เสียงบี๊บเตือน), ปลดล็อก concept ใหม่มีเสียงแฟนแฟร์สั้น
- **ปิดเพลงแยกจากเสียงได้:** คนชอบฟังเพลงตัวเองตอนเขียนโค้ด

## UX และหน้าจอ

หน้าจอหลักแบ่งเป็น editor ทางซ้ายและแล็บทางขวา เพื่อให้ผู้เล่นเห็นผลของโค้ดทันทีโดยไม่ต้องสลับหน้า

### Layout

- **แถบบน:** ทรัพยากร (Essence, Crystal, Mana) และปุ่มควบคุมเวลา
- **ซ้าย:** editor มีแท็บต่อ class และ autocomplete ที่แสดงเฉพาะ API ที่ปลดล็อกแล้ว
- **ขวา:** แล็บแบบ pixel art คลิกสัตว์ตัวไหนก็เห็นค่าของมันแบบสด
- **ล่าง:** คอนโซลที่เป็นเสียงของ Ref แสดง log และ error เป็นภาษาคน
- **Overlay:** Tech tree, Codex และผังตระกูล เปิดด้วยปุ่มลัด

### Error กลายเป็นตัวละคร

ปกติ error ทำให้มือใหม่กลัว แต่ในเกมนี้ error คือสิ่งที่เห็นได้บนตัวสัตว์ ทำให้ debug กลายเป็นการดูแลสัตว์

| Error | สิ่งที่เห็นในเกม | Ref พูดว่า |
| --- | --- | --- |
| อ่านค่าจาก `undefined` | สัตว์ทำหน้างง มีเครื่องหมาย ? บนหัว | "มันหาสิ่งที่นายสั่งไม่เจอ ลองเช็คบรรทัด 12" |
| Infinite loop | สัตว์หมุนติ้วจนเวียนหัว ระบบหยุดให้อัตโนมัติเมื่อ Mana หมด | "มันวนไม่จบ เงื่อนไขหยุดอยู่ไหน?" |
| Syntax error | เส้นหยักใน editor สัตว์ยังทำงานด้วยโค้ดเวอร์ชันล่าสุดที่ใช้ได้ | อธิบายเป็นภาษาไทยง่ายๆ |
| ใช้ฟีเจอร์ที่ยังไม่ปลดล็อก | แม่กุญแจที่บรรทัดนั้น | "ยังไม่ได้วิจัย for loop นะ" |
| Type ไม่ตรง (องก์ 4) | ขีดแดงก่อนรัน สัตว์ไม่ถูกส่งไปห้องผิด | "วัวว่ายน้ำไม่เป็น" |

### ฟีเจอร์สำคัญเพื่อการสอน

- **Hot reload:** กด save แล้วสัตว์ทุกตัวเปลี่ยนพฤติกรรมและร่างทันที โดยค่าที่สะสมไม่หาย
- **Step debugger:** หยุดเวลา กดทีละ tick แล้วเห็นว่าสัตว์ที่เลือกกำลังรันบรรทัดไหน เป็นเครื่องมือที่มือใหม่ต้องการที่สุดแต่ไม่ค่อยมีใครสอน
- **บันไดคำใบ้ 3 ขั้น:** ทิศทาง, ตัวอย่างโค้ดบางส่วน, แล้วถึงเฉลย ใช้เฉลยได้ไม่เสียอะไร แค่ไม่ได้ตรา "ทำเอง" ในภารกิจนั้น
- **ควบคุมเวลา:** หยุด, 1x, 4x, 16x

### การเข้าถึง

- สลับภาษาไทยและอังกฤษได้ทุกเมื่อ ส่วนโค้ดเป็นภาษาอังกฤษเสมอ
- ปรับขนาดตัวอักษรใน editor ได้
- ธาตุแยกด้วยรูปทรงอนุภาคด้วย ไม่ใช้แค่สี เพื่อให้คนตาบอดสีแยกได้

## Tech architecture

ทั้งเกมเป็น TypeScript โค้ดชุดเดียวที่ออกได้ทั้งเว็บ (browser บนคอมพิวเตอร์) และ Steam (Windows, Mac, Linux) โดยส่วนที่ยากที่สุดคือ sandbox ที่รันโค้ดผู้เล่นอย่างปลอดภัยและคุม tick ได้

| ชั้น | ตัวเลือก | เหตุผล |
| --- | --- | --- |
| ภาษาและ build | TypeScript + Vite | ถนัดอยู่แล้ว build เร็ว |
| UI | React | แผงเมนู, tech tree, codex |
| โลกของเกม | PixiJS (WebGL 2D) | วาดสัตว์หลายร้อยตัวและอนุภาคได้ลื่น |
| Editor | Monaco + TS language service | autocomplete และ type error ฟรี ส่ง `.d.ts` ตามองก์เพื่อซ่อน API ที่ยังไม่ปลดล็อก |
| Sandbox | QuickJS (wasm) ใน Web Worker | โค้ดผู้เล่นแตะ DOM ไม่ได้ หยุด infinite loop ได้ด้วย interrupt และนับงบ Mana ได้ |
| แปลง TS เป็น JS | `ts.transpileModule` หรือ esbuild-wasm | เร็วพอทำทุกครั้งที่ save |
| ล็อกฟีเจอร์ภาษา | TypeScript Compiler API เดิน AST | เจอ syntax ที่ยังไม่ปลดล็อก เช่น `ClassDeclaration` ก็แจ้งพร้อมเลขบรรทัด |
| Simulation | fixed tick 10 ครั้งต่อวินาที + RNG มี seed | ผลเหมือนเดิมทุกครั้ง ใช้ตรวจ leaderboard ด้วยการ replay ได้ |
| Save | IndexedDB (เว็บ) และ Steam Cloud (desktop) | เก็บโค้ดผู้เล่นและสถานะแล็บ |
| Desktop | Electron + steamworks.js | achievement, cloud save, leaderboard |

**การไหลของข้อมูลต่อ tick:** simulation ส่งสถานะสัตว์เข้า Worker, Worker เรียก `update()` ของสัตว์ทุกตัวใน QuickJS VM เดียว แล้วส่งชุด "คำสั่ง" (move, eat, gather) กลับมา simulation ตรวจความถูกต้องและอัปเดตโลก แล้ว Pixi วาดผล โค้ดผู้เล่นจึงแก้สถานะโลกตรงๆ ไม่ได้ ซึ่งเป็นทั้งความปลอดภัยและเหตุผลรองรับเรื่อง private field ในเนื้อเรื่อง

### Content เป็นข้อมูล ไม่ใช่โค้ด

ภารกิจ ชิ้นส่วน สูตรสายพันธุ์ และบทพูดของ Ref เก็บเป็นไฟล์ JSON แยกจาก engine เพิ่มคอนเทนต์ได้โดยไม่ต้องแก้โค้ดเกม และเป็นรูปแบบเดียวกับที่ Workshop จะใช้ทีหลัง

```json
{
  "id": "act3-fire-slime",
  "act": 3,
  "requires": ["extends"],
  "goal": { "type": "creatureInRoom", "room": "forge", "count": 3 },
  "reward": { "crystal": 50, "unlockPart": "horns-small" },
  "hintsKey": "act3-fire-slime"
}
```

ข้อความไทยและอังกฤษอยู่ในไฟล์ภาษาแยก อ้างด้วย key เพื่อให้แปลเพิ่มได้ง่าย

### กันโค้ดผู้เล่นหาย

โค้ดที่ผู้เล่นเขียนคือของที่มีค่าที่สุดในเซฟ

- **Auto-save** ทุกครั้งที่หยุดพิมพ์ 2 วินาที และทุกครั้งที่ save สำเร็จ
- **ประวัติเวอร์ชันต่อ class:** เก็บ 20 เวอร์ชันล่าสุด ย้อนกลับได้ในคลิกเดียว (ใช้ในเกมเป็น "เครื่องย้อนเวลา" ของแล็บ ปูไปสู่ concept ของ git แบบเบาๆ)
- **Export/Import เซฟ** เป็นไฟล์เดียว ย้ายระหว่างเว็บกับ Steam ได้
- **กู้คืนหลังเกมพัง:** ถ้าโค้ดใหม่ทำให้แล็บรันไม่ได้ เปิดเกมมาจะถามว่าจะย้อนไปเวอร์ชันที่รันได้ล่าสุดไหม

## Roadmap

เริ่มจาก prototype ที่พิสูจน์แค่เรื่องเดียว: พิมพ์ `extends` แล้วเห็นสัตว์เปลี่ยนร่างสดๆ แล้วคนเล่นรู้สึกว้าวจริงไหม ถ้าไม่ผ่าน ให้แก้แกนเกมก่อนทำส่วนอื่น

| เฟส | ขอบเขต | งานหลัก | ผ่านเมื่อ |
| --- | --- | --- | --- |
| 0 · Prototype | ห้องเดียว บนเว็บ | สไลม์ + สายไฟ, class + extends, Morph + hot reload | ผู้ทดสอบเล่นต่อเองเกิน 15 นาที |
| 1 · Web demo | องก์ 1–2 | tutorial กับ Ref, ทรัพยากร + วิจัย, 15 สายพันธุ์ | คนเกินครึ่งจบองก์ 1 ในรอบ playtest |
| 2 · Steam demo | องก์ 1–3 | หน้าร้าน Steam, ลง Next Fest, ไทย + อังกฤษ | feedback นิ่งและมี wishlist |
| 3 · 1.0 ฟรี | องก์ 1–5 | Codex 60+ ตัว, leaderboard, Steam Workshop | ต่อจากนี้: Arena PvP และองก์เสริม |

ทุกเฟสปล่อยบนเว็บก่อนเสมอ เพราะ แชร์ลิงก์ให้คนเล่นทดสอบได้ทันที ส่วนค่า Steam Direct $100 จ่ายตอนเข้าเฟส 2 เมื่อแกนเกมนิ่งแล้ว

### ขอบเขต prototype (เฟส 0)

- [ ] หน้าจอ editor (Monaco) + แล็บ (Pixi) ห้องเดียว
- [ ] base class `Creature` กับ method 3 ตัว: `move`, `eat`, `gather`
- [ ] sandbox QuickJS เรียก `update()` ทุก tick
- [ ] Morph: `body`, `element`, `horns` แสดงผลบนตัวสัตว์
- [ ] Hot reload ทั้งฝูงตอน save
- [ ] ภารกิจทดสอบ 3 อัน: เก็บของ, สร้างฝูงด้วย class, ทำ FireSlime ด้วย extends
  - อัปเดต 19 ต.ค. 2026: ขยายเป็นองก์ 1–3 ในห้องเดียว เริ่มจาก JavaScript พื้นฐานก่อน class (โค้ดองก์ 1 สั่ง `slime` ทีละบรรทัด รอทำเสร็จ) ภารกิจ 7 อัน: ตั้งชื่อ → เก็บ 5 ก้อน → if → loop → function → ฝูง 10 ตัวด้วย class → extends เปลี่ยนธาตุ
- [ ] playtest กับผู้เล่นมือใหม่ 5 คน

### เวลาของผู้พัฒนา

โปรเจกต์นี้ทำคนเดียวควบงานประจำและงานฟรีแลนซ์ ความเสี่ยงอันดับหนึ่งจึงไม่ใช่เทคนิค แต่คือหมดแรงก่อนเกมเสร็จ

- กำหนด **ชั่วโมงต่อสัปดาห์ที่ทำได้จริง** และทำสม่ำเสมอ ดีกว่าทำหนักเป็นช่วงแล้วหายไป
- ตั้ง **เส้นตายให้ prototype** ถ้าถึงเส้นแล้วยังไม่ว้าว ให้หยุดคิดแกนเกมใหม่ ไม่ทำต่อเพื่อหวังว่าจะดีขึ้นเอง
- **ตัดฟีเจอร์ก่อนเลื่อนเวลา** ทุกเฟสมีรายการ "ตัดได้ถ้าจำเป็น" เตรียมไว้
- ใช้ AI coding agent ช่วยงาน boilerplate (UI, ระบบเซฟ, เครื่องมือ content) เก็บแรงไว้กับส่วนที่เป็นหัวใจ คือ Morph และความรู้สึกตอนเล่น
- Devlog ช่วยให้มีแรงจูงใจ เพราะมีคนรอดูความคืบหน้า

## ความเสี่ยงและคำถามที่ยังเปิดอยู่

ความเสี่ยงใหญ่ที่สุดคือขอบเขตงานบานจนทำไม่จบ จึงต้องพิสูจน์ "ความว้าว" ของระบบ Morph ใน prototype ก่อนลงทุนส่วนอื่น

| ความเสี่ยง | ผลกระทบ | ทางรับมือ |
| --- | --- | --- |
| ขอบเขตบาน (5 องก์, 100 สายพันธุ์) | ทำไม่จบ | ตัดเป็นเฟส ปล่อยองก์ 1 ถึง 2 บนเว็บก่อน |
